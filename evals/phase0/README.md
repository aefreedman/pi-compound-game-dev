# Phase 0 behavioral eval seeds

These package-owned cases preserve failure and correction themes before `pi-compound-game-dev` is decomposed. They are an opt-in evaluation contract, not part of `npm test`.

`cases.json` defines four comparison conditions:

- the exact legacy reader baseline;
- packed canonical packages using named owner skills/provider guidance;
- packed canonical packages with `pi-game-dev` compatibility facades;
- an optional catalog prototype used only if the canonical arm does not meet the decision thresholds.

Cases grade observable outcomes rather than one exact tool sequence. The reference-discovery case specifically measures whether co-location and ordinary model/file-tool behavior make a shared `pi-package-references` package unnecessary.

## Pilot requirements

Before running model trials:

1. create synthetic temporary Git and Plastic fixture roots; never mutate live repositories;
2. provide deterministic docs/todos and Unity result fixtures;
3. disable production integrations and mutation tools; the unrelated-task negative control may use one allowlisted synthetic-root write capability whose diff is captured and which rejects every path outside that root;
4. use fresh Pi sessions for every condition/case/trial;
5. retain only sanitized aggregate results;
6. run at least three trials per condition on an approved GPT-5.6 model.

Reference cases pin exact resource IDs, competing public resources, private/absent/ambiguous controls, normalized trace fields, and pass thresholds. Runner construction and live pilots occur when packed canonical packages exist at the Phase 1 extraction checkpoint; Phase 0 does not treat the unexecuted canonical arm as evidence.
